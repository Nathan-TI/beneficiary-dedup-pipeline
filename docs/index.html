How it works

The same steps a registration team follows before a distribution list goes out.

GenerateSynthetic registrations with planted duplicates, sibling look-alikes and typical field errors.
Check quality10 rules for missing, invalid and implausible values, logged one row per issue.
StandardiseClean names, a phonetic key for spelling variants, phone numbers in one format, parsed dates.
BlockOnly compare records that share a key (name key, phone, ID, DOB), so far fewer pairs need scoring.
ScoreWeighted similarity across 8 fields, plus rules (siblings, different IDs, name-only matches).
MergeAuto-merge confident pairs, queue borderline ones for review, and build one golden record per person.

Accuracy against ground truth

Because the data is synthetic, every true duplicate is known, so accuracy can be measured rather than guessed. Exact matching finds only 33% of duplicate pairs. Fuzzy matching with domain rules finds 93.5% automatically with 0 false merges, and 95.2% once the review queue is worked.

Where the scores fall

Each candidate pair gets a 0–1 score. Pairs at or above 0.88 merge automatically, pairs from 0.75 up to 0.88 go to a reviewer (188 pairs), and everything below is kept apart.
